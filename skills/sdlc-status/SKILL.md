# sdlc-status

## 输入

- 当前项目的结构化事件、正式产物、审核记录、任务合同、任务运行轮次和 CHG 工作区。
- 直接执行：

`codex-sdlc status`

## 执行

1. 直接读取命令输出，不手工拼接状态。
2. 文档优先任务主线只使用 `planning_tasks`、`ready_for_development`、`developing`、`verifying`、`accepted`。
3. `planning_tasks` 要展示任务导入、阻塞条件、规划代码证据和当前 `task_plan` 审核状态。
4. `ready_for_development` 要展示当前有效审核和可执行任务。
5. `developing` 要展示当前任务、运行号、`reading`、`active` 或 `stale` 状态，以及读取清单和范围检查结果。
6. 有结构化变更时展示 `CHG-xxx` 工作区、基础版本、预计版本、受影响审核和保护状态。
7. 既有档案只读结果单独展示，不能改变当前需求状态、候选任务或运行轮次。

## 输出

- 当前 DRAFT、REQ、任务、审核、任务运行轮次和 CHG 的正式状态摘要。
- 与 `$sdlc-next` 同一套结构化状态计算出的下一步。
- 损坏、漂移、阻塞和事务恢复结果的明确说明。

## 阻塞条件

- 事件、正式文件、审核输入哈希或运行轮次互相不一致。
- 当前任务指针缺失、多个活动轮次冲突或读取清单损坏。
- CHG 基础版本或预计版本漂移。
- 状态命令无法完成既有事务的确定性恢复。

## 审核点

本技能只读展示 `requirement_split`、`integrated_design`、`task_plan` 三类审核的当前结果，不创建、不提交、不修改审核。

## 停止位置

状态和当前下一步展示完成后停止。本技能不确认读取、不启动任务、不生效变更，也不修改任何业务状态。

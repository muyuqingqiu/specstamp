# sdlc-goal

## 输入

- 用户明确设置的 Goal、允许范围和完成门槛。
- 当前正式状态和唯一下一步：

`codex-sdlc status`

`codex-sdlc next`

- 当前任务审核、任务合同、读取清单、运行轮次、测试、验收、反馈和结构化变更状态。

## 执行

1. 每轮先执行状态和下一步命令，只推进当前主推荐。
2. `planning_tasks`：补齐三套任务输入或等待当前 `task_plan` 独立审核。审核为 `needs_fix` 或 `stale` 时返修整套任务后重新审核；有阻塞项时不派开发。
3. `ready_for_development`：按正式依赖选择唯一任务并直接开工：

`codex-sdlc task REQ-001 T-001`

4. `developing`：保持同一个任务处理当前运行轮次。`reading` 时完整读取清单并由同任务确认；`active` 时继续实现、测试、人工验收和证据登记；开发中复核：

`codex-sdlc task-run-check REQ-001 T-001`

5. 当前轮次为 `stale` 时停止开发，按正式暂停和恢复入口处理上游漂移，再创建递增的新轮次。旧轮次和证据保持只读。
6. 出现正式需求或设计变化时进入 CHG 工作区，提交完整预计版本并完成受影响审核；不能把变化直接写进当前任务说明。
7. 当前任务通过全部完成门禁后调用 `$sdlc-task-done`。状态变化后重新执行 `codex-sdlc status` 和 `codex-sdlc next`，不能预判后续阶段。
8. `verifying` 只推进需求级回归和验收；`accepted` 停止开发调度。

## 输出

- 每轮正式状态、执行动作、实际结果和下一步。
- 当前任务运行轮次、读取确认、测试、人工验收、反馈和范围检查证据。
- Goal 完成时与目标绑定的最终验证结果；未完成时保留清楚的剩余项。

## 阻塞条件

- 下一步候选不唯一或与状态输出不一致。
- 整套任务审核、正式引用、规划代码证据或依赖失效。
- 多个活动任务运行轮次、任务身份不一致或当前轮次为 `stale`。
- 测试、人工验收、反馈或范围门禁未完成。
- 结构化变更缺少完整预计版本、受影响审核或用户确认。
- 继续执行需要修改未授权路径、覆盖来源不明改动或执行高风险动作。

## 审核点

Goal 只协调现有正式审核：建档前需求和设计审核、建档后整套任务审核、结构化变更影响到的对应审核。不能新增重复审核阶段，也不能用开发任务自述替代独立审核结果。

## 停止位置

Goal 真正达到完成门槛后停止并报告最终状态。遇到明确阻塞时保留现场和最少缺失资料；不能因为单轮结束、测试仍在运行或后续任务尚未审核就虚报完成。

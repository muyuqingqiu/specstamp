## 1. 环境识别顺序

按下面顺序判断当前要用哪套策略：

1. 用户显式指定运行环境。
2. 当前工具或线程入口已经明显说明平台：
   - Codex 线程工具：按 Codex 规则。
   - Claude Code / `cc-claude-code`：按 Claude 规则。
   - DevEco / `deveco-code`：按 DevEco 规则。
3. 识别不到时，使用“通用兜底环境”。

环境识别不到不算阻塞；先走兜底规则，再把无法确认写进记录。

## 2. 复杂度判断口径

### 高复杂度

命中任一项就按高复杂度处理：

- 多文件实现或返修。
- 共享逻辑、全局状态、路由、存储、配置链路改动。
- 测试链路长，或要做多轮根因判断。
- 线程替换后需要重新接手复杂上下文。
- 用户明确要求深度思考、重点排查或高质量复核。

### 中复杂度

同时满足这些特征时，按中复杂度处理：

- 任务边界清楚。
- 影响范围有限，但不只单文件。
- 需要常规测试或验收。
- 不需要大范围重构判断。

### 低复杂度

同时满足这些特征时，按低复杂度处理：

- 主要是只读查找、资料整理、进度回写或小范围核对。
- 单文件或很小范围改动。
- 测试链路短。
- 不需要复杂取舍判断。

## 3. 各环境默认模型档位

### Codex 环境

| 复杂度 | 推荐模型档位 | 默认请求模型 | 判断原因口径 |
| --- | --- | --- | --- |
| 高复杂度 | 高能力档 | `gpt-5.5` | 需要更强判断、返修或复杂调度 |
| 中复杂度 | 标准档 | `gpt-5.4` | 任务清楚但仍有开发或测试链路 |
| 低复杂度 | 经济档 | `gpt-5.4-mini` | 以查找、整理、轻验证为主 |

### Claude Code 环境

| 复杂度 | 推荐模型档位 | 默认请求模型 | 判断原因口径 |
| --- | --- | --- | --- |
| 高复杂度 | 高能力档 | `opus` | 复杂实现、返修、重判断 |
| 中复杂度 | 标准档 | `sonnet` | 常规开发、常规测试 |
| 低复杂度 | 轻量档 | `sonnet` | 当前无更轻模型时继续用 `sonnet` 做轻任务 |

### DevEco / 专用 Agent 环境

| 复杂度 | 推荐模型档位 | 默认请求模型 | 判断原因口径 |
| --- | --- | --- | --- |
| 高复杂度 | 高能力档 | 环境里的高能力模型 | 高风险实现、复杂返修 |
| 中复杂度 | 默认稳定档 | 环境里的默认稳定模型 | 常规开发与测试 |
| 低复杂度 | 经济档 | 环境里的低成本模型；没有就继续用默认稳定模型 | 轻任务、轻验证 |

### 通用兜底环境

| 复杂度 | 推荐模型档位 | 默认请求模型 | 判断原因口径 |
| --- | --- | --- | --- |
| 高复杂度 | 高能力档 | 由当前环境可用模型决定 | 复杂任务优先更强模型 |
| 中复杂度 | 标准档 | 由当前环境可用模型决定 | 常规任务走稳定模型 |
| 低复杂度 | 经济档 | 由当前环境可用模型决定 | 轻任务优先省成本 |

## 4. 各环境默认思考深度

### Codex 环境

| 复杂度 | 默认思考深度 | 原因 |
| --- | --- | --- |
| 高复杂度 | `high` | 需要更完整的任务判断与返修决策 |
| 中复杂度 | `medium` | 开发和测试有一定链路，但边界清楚 |
| 低复杂度 | `low` | 以查找、整理、轻验证为主 |

### Claude Code 环境

| 复杂度 | 默认思考深度 | 原因 |
| --- | --- | --- |
| 高复杂度 | `high` | 复杂实现和高风险返修需要更深推理 |
| 中复杂度 | `medium` | 常规开发和常规测试足够 |
| 低复杂度 | `low` | 轻任务不需要拉高思考成本 |

### DevEco / 专用 Agent 环境

| 复杂度 | 默认思考深度 | 原因 |
| --- | --- | --- |
| 高复杂度 | 高档思考深度 | 复杂问题优先保证判断质量 |
| 中复杂度 | 中档思考深度 | 常规任务平衡速度和质量 |
| 低复杂度 | 低档思考深度 | 轻任务优先快和稳 |

### 通用兜底环境

| 复杂度 | 默认思考深度 | 原因 |
| --- | --- | --- |
| 高复杂度 | 高档 | 复杂任务优先判断质量 |
| 中复杂度 | 中档 | 常规任务保持平衡 |
| 低复杂度 | 低档 | 轻任务不额外放大成本 |

用户明确指定模型或思考深度时，覆盖默认值，但仍要记录“为什么接受这次覆盖”。

## 5. 主线程必须记录的字段

每次派线程前，至少记录这些字段：

- 当前环境
- 复杂度判断：高 / 中 / 低
- 推荐模型档位
- 请求模型
- 实际模型
- 请求思考深度
- 实际思考深度
- 模型判断原因
- 思考深度判断原因
- 是否命中用户覆盖

### 推荐的简短写法

```text
模型与思考决策：
- 环境：Codex
- 复杂度：高
- 推荐模型档位：高能力档
- 请求模型：gpt-5.5
- 请求思考深度：high
- 模型原因：当前任务涉及多文件返修和最终验收，普通模型容易漏掉上下文
- 思考原因：需要先判断线程替换，再安排返修和复检，链路较长
```

### 实际值拿不到时

- 实际模型：`null`
- 实际思考深度：`null`
- 说明原因：平台或工具当前不可见

# SpecStamp 常见问题

## SpecStamp 的项目数据存在哪里？

需求、设计、任务、证据和运行状态保存在项目目录的 `.codex-sdlc/` 里。备份快照默认保存在 `$HOME/.codex/sdlc/backups`。这些数据不依赖云端账号，也不会自动上传。

## 支持哪些系统？

支持 macOS 和 Linux 等 POSIX 系统。运行依赖 `fcntl` 和 POSIX shell，暂不支持 Windows。

## 支持云端多人实时协作吗？

不支持。项目定位是本机优先工具，适合个人开发者和小型团队；多人实时协作需要外部同步方案。

## 和 Codex、Claude Code 怎么配合？

通过 `agent-sync` 把同一套技能同步到三套入口：

- Codex：`sdlc-*` 技能。
- Claude Code：`/sdlc-*` 命令。
- 通用 Agent：共享技能。

同步前用 `specstamp agent-sync --dry-run` 预览，确认后用 `--confirm` 写入，用 `--check` 复核。

## 已有项目怎么接入？

1. 在项目根目录执行 `specstamp init`。
2. 用 `specstamp material` 把旧需求文档、技术方案、设计稿和截图原样归档。
3. 用 `specstamp discuss --file` 记录讨论结论，再按 `next` 的提示继续。

## 换 Agent 或重开会话后，项目事实怎么接上？

所有事实都写在项目的 `.codex-sdlc/` 里。新会话先执行 `specstamp status` 和 `specstamp next`，再让 Agent 按提示继续。切换分支或工作树后，身份校验会阻止状态串用，必要时用 `backup-list` 和 `restore` 找回对应快照。

## 任务怎么算完成？

任务完成前必须登记证据：测试命令、整数退出码、结果、来源文件和 SHA-256 原值，并逐项核对功能、验收点和测试项。`task-done` 会自动验证这些门禁，缺少证据会拒绝完成。

## 需求变了怎么办？

把变化走显式变更流程：`change-plan` 规划、`change-create` 建工作区、`change-package` 提交变更包、`change-accept` 生成新的生效版本。变更会影响的任务会被标记和保护，不会悄悄漂移。

## 安装报错怎么办？

先执行 `specstamp doctor-install` 做只读检查，它会显示具体路径和中文修复命令。常见处理：

- 命令找不到：`export PATH="$HOME/.local/bin:$PATH"`。
- 受管环境缺失：重跑安装脚本。
- `CODEX_SDLC_PYTHON` 配置不可用：先 `unset CODEX_SDLC_PYTHON`，再重新安装。

## 怎么卸载？

- 项目内：先用 `specstamp clean` 预览要清理的产物，确认后执行 `specstamp clean-confirm`。
- 全局安装目前没有一键卸载命令。需要手动移除时，只删除 `$HOME/.local/bin/specstamp`、`$HOME/.local/bin/codex-sdlc` 和 `agent-sync` 生成的受管条目，不要直接删除整个 `$HOME/.codex/skills`、`$HOME/.agents` 或 `$HOME/.claude/commands` 目录。

## 临时体验会写全局目录吗？

不会。`/tmp` 临时环境的安装和初始化只写在 `/tmp` 下。只有执行 `scripts/install_specstamp.py --confirm-agent-sync` 或 `specstamp agent-sync --confirm` 才会写入全局目录。

## `codex-sdlc` 命令还能使用吗？

可以。`specstamp` 是主命令，`codex-sdlc` 作为兼容命令继续提供相同功能。

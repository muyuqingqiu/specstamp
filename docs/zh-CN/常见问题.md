# SpecStamp 常见问题

## SpecStamp 的项目数据存在哪里？

需求、设计、任务、证据和运行状态保存在项目目录的 `.codex-sdlc/` 里。备份快照默认保存在 `$HOME/.codex/sdlc/backups`。这些数据不依赖云端账号，也不会自动上传。

## 支持哪些系统？

支持 macOS 和 Linux 等 POSIX 系统。运行依赖 `fcntl` 和 POSIX shell，暂不支持 Windows。

## 支持云端多人实时协作吗？

不支持。项目定位是本机优先工具，适合个人开发者和小型团队；多人实时协作需要外部同步方案。

## 和 Codex、Claude Code 怎么配合？

SpecStamp 是产品名，不同客户端使用不同的调用形式：

- 终端：`specstamp next`。
- Codex：`$sdlc-next`。
- Claude Code：`/sdlc-next`。

在终端中先用 `specstamp agent-sync --dry-run` 预览，再用 `specstamp agent-sync --confirm` 同步，最后用 `specstamp agent-sync --check` 复核。Codex 会得到 `$sdlc-*` 技能，Claude Code 会得到 `/sdlc-*` 命令，通用 Agent 目录会得到同一份受管技能来源。`sdlc-*` 是为兼容已有使用方式保留的名称；这些入口都属于 SpecStamp，不是不同产品。

## 已有项目怎么接入？

1. 在项目根目录执行 `specstamp init`。
2. 用 `specstamp material` 把旧需求文档、技术方案、设计稿和截图原样归档。
3. 用 `specstamp discuss --file` 记录讨论结论，再按 `specstamp next` 的提示继续。

## 换 Agent 或重开会话后，项目事实怎么接上？

所有事实都写在项目的 `.codex-sdlc/` 里。通过终端继续时，先执行 `specstamp status` 和 `specstamp next`；在 Codex 中继续时，使用 `$sdlc-status` 和 `$sdlc-next`；在 Claude Code 中继续时，使用 `/sdlc-status` 和 `/sdlc-next`。切换分支或工作树后，身份校验会阻止状态串用，必要时通过对应入口使用备份和恢复能力。

## 任务怎么算完成？

任务完成前必须登记证据：测试命令、整数退出码、结果、来源文件和 SHA-256 原值，并逐项核对功能、验收点和测试项。`specstamp task-done` 会自动验证这些门禁，缺少证据会拒绝完成。

## 需求变了怎么办？

通过终端使用显式变更流程：`specstamp change-plan` 规划、`specstamp change-create` 建工作区、`specstamp change-package` 提交变更包、`specstamp change-accept` 生成新的生效版本。变更会影响的任务会被标记和保护，不会悄悄漂移。

## 安装报错怎么办？

先执行 `specstamp doctor-install` 做只读检查，它会显示具体路径和中文修复命令。常见处理：

- 命令找不到：`export PATH="$HOME/.local/bin:$PATH"`。
- 受管环境缺失：重跑安装脚本。
- `CODEX_SDLC_PYTHON` 配置不可用：先 `unset CODEX_SDLC_PYTHON`，再重新安装。

## 怎么卸载？

- 项目内：先用 `specstamp clean` 预览要清理的产物，确认后执行 `specstamp clean-confirm`。
- 全局安装目前没有一键卸载命令。需要手动移除时，只删除 `$HOME/.local/bin/specstamp`、`$HOME/.local/bin/codex-sdlc` 和 `specstamp agent-sync` 生成的受管条目，不要直接删除整个 `$HOME/.codex/skills`、`$HOME/.agents` 或 `$HOME/.claude/commands` 目录。

## 临时体验会写全局目录吗？

不会。`/tmp` 临时环境的安装和初始化只写在 `/tmp` 下。只有执行 `scripts/install_specstamp.py --confirm-agent-sync` 或 `specstamp agent-sync --confirm` 才会写入全局目录。

## `codex-sdlc` 命令还能使用吗？

可以。`specstamp` 是主命令，`codex-sdlc` 作为兼容命令继续提供相同功能。

# SpecStamp 理念与灵感

## 设计理念

SpecStamp 的设计理念围绕下面几条展开。

### 文件比聊天记录可靠

聊天记录会丢、会乱、会过时；文件会留在项目里，谁都能打开看。项目的事实应该落在文件里，而不是落在某一次对话里。

### 证据比 Agent 自述可靠

“做完了”不是结论，能复现的命令、能核对的退出码、能比对的文件哈希才是结论。证据让验收有标准，让返修有依据。

### 显式变更比悄悄漂移可靠

需求变化是项目里最正常的事。把变化明确记下来，告诉哪些设计、任务和验收受影响，比让代码悄悄偏离需求更可靠。

### Agent 可以更换，项目事实不能丢

模型、工具和会话都会换，项目需求、设计、任务和证据应该留在项目里，随时可以被下一个 Agent 接着读。

### 小步推进，每一步都可以检查和恢复

需求拆小、任务拆小、每一步都有编号、哈希和备份。走错了可以回退，不会把整个项目拖下水。

### 人负责决定，Agent 负责整理和执行

AI 擅长理解自然语言、整理结构和执行重复工作；关键的业务判断、整体确认和验收决定始终由人来做。CLI 只做确定性的保存、编号、校验和引用，不替人解释业务语义。

## 灵感来源

- 规格驱动开发：先有明确的需求和规格，再谈实现。
- 文档优先开发：文档不是开发的副产品，而是开发的依据。
- Unix 可组合工具：每个命令做好一件事，命令之间用文件和约定连接。
- 事件记录：把发生过的变化按顺序留下来，事后可回放、可核对。
- 可追溯交付：从原始意图到最终交付，每一步都能说明来源和依据。

## 适用边界

- 本机优先：数据保存在项目目录，不依赖云端账号。
- 工具无关：Codex、Claude Code、通用 Agent 都可以接入同一套流程。
- 平台限制：支持 macOS 和 Linux 等 POSIX 系统，暂不支持 Windows。
- 协作边界：没有云端多人实时协作能力，适合个人开发者和小型团队。
